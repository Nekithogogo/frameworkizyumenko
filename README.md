# CertHub — сервис управления SSL-сертификатами

Приложение для учета организаций, их доменов и выпущенных для них
SSL-сертификатов с контролем сроков действия. Консольная версия
(ПР1–ПР3) дополнена веб-интерфейсом на Django (ПР5), страницы которого
формируются шаблонами Django (ПР6). Веб-интерфейс получает данные из базы
SQLite с помощью SQL-запросов (ПР7).

## Используемые технологии

- Python 3.11;
- Django 5.2 — веб-фреймворк;
- Django Template Language (DTL) — шаблоны страниц;
- HTML5 — разметка веб-страниц;
- CSS3 и Bootstrap 5.3 — оформление страниц, собственные стили проекта;
- JavaScript — небольшое поведение интерфейса;
- SQLite и SQL — база данных веб-интерфейса, модуль `sqlite3`;
- JSON — исходные данные и хранилище консольной версии;
- pytest — автоматизированные тесты;
- flake8 — проверка качества кода.

## Назначение

CertHub помогает вести учет SSL-сертификатов: для каких доменов они
выпущены, какой организации принадлежат и когда истекает их срок
действия. Сервис заранее предупреждает об истекающих сертификатах,
чтобы сайт не остался без защищенного соединения.

## Целевая аудитория

Системные администраторы и DevOps-инженеры компаний, у которых много
доменов, а также сотрудники хостинг-провайдеров и удостоверяющих центров,
сопровождающие сертификаты клиентов.

## Предметная область

Организация владеет доменами. Для домена выпускается SSL-сертификат
определенного типа (DV, OV, EV) на ограниченный срок.

## Основные сущности (классы)

Все классы находятся в пакете `models/`. Классы `Organization`, `Domain` и
`Certificate` наследуют базовый класс `Entity` (идентификатор `id` и метод
`to_dict()`); хранилище сохраняет объекты любого из них одной функцией
`save_objects()` — это пример полиморфизма.

### Organization — организация (`models/organizations.py`)

Атрибуты: `id`, `name`, `inn`, `email`. ИНН инкапсулирован: свойство
`inn` проверяет формат (10 или 12 цифр) при каждом изменении.

Методы: `validate_inn()` (`@staticmethod`), `from_data()` (`@classmethod`),
`to_dict()`, `__str__()`.

### Domain — домен (`models/domains.py`)

Атрибуты: `id`, `name`, `organization` (объект `Organization` — владелец).
Имя домена приводится к нижнему регистру и проверяется свойством `name`.

Методы: `is_valid_name()` (`@staticmethod`), `zone` (свойство — доменная
зона), `belongs_to()` — принадлежит ли домен организации, `to_dict()`,
`__str__()`.

### Validity — срок действия (`models/validity.py`)

Атрибуты: `valid_from`, `valid_to` (даты). Своего идентификатора не имеет:
существует только в составе сертификата.

Методы:

- `is_valid_term()` (`@staticmethod`) — срок от 1 до 398 дней;
- `from_days()`, `from_data()` (`@classmethod`) — создание срока;
- `days_total` (свойство), `days_left()` — длительность и остаток дней;
- `has_started()`, `is_expired()`, `is_expiring()`, `contains()` — состояние срока на дату;
- `overlaps()` — пересечение с другим сроком;
- `next_start()` — дата начала следующего срока (продление);
- `to_dict()`, `__str__()`.

### Certificate — сертификат (`models/certificates.py`)

Атрибуты: `id`, `serial_number`, `cert_type` (DV/OV/EV), `domain`
(объект `Domain`), `organization` (объект `Organization` — заказчик),
`validity` (объект `Validity`), `is_revoked`.

Методы:

- `revoke()` — отзыв;
- `is_valid_on()` — защищает ли сертификат домен в указанный день;
- `blocks()` — мешает ли выпуску нового сертификата на заданный срок;
- `get_status()`, `get_status_title()` — статус: еще не действует,
  действует, скоро истекает, истек, отозван;
- `days_left()`, `to_dict()`, `__str__()`.

### Взаимодействие объектов

```
Certificate
├── domain ──────→ Domain ──→ organization ──→ Organization
├── organization ─→ Organization
└── validity ────→ Validity
```

Данные связанных объектов доступны напрямую: `certificate.domain.name`,
`certificate.organization.inn`, `certificate.validity.valid_to`.
Функции модулей работают с коллекциями `List[Organization]`,
`List[Domain]`, `List[Certificate]`.

## Правила предметной области

- сертификат выпускается только организации — владельцу домена;
- срок действия — от 1 до 398 дней;
- у домена не может быть двух неотозванных сертификатов с пересекающимся
  сроком действия;
- за 30 дней до окончания срока сертификат считается истекающим;
- продление — выпуск нового сертификата, начинающего действовать на
  следующий день после окончания старого;
- отозванный сертификат не защищает домен и не мешает выпуску нового.

## Возможности

- просмотр и добавление организаций (с проверкой ИНН);
- просмотр доменов, поиск по имени, отбор по зоне, добавление;
- просмотр сертификатов, упорядоченных по дате окончания, со статусом;
- проверка сертификатов домена и текущего срока действия;
- выпуск, продление и отзыв сертификатов;
- список сертификатов, требующих продления;
- хранение данных между запусками в JSON-файлах.

## Хранение данных

Исходные данные проекта лежат в JSON-файлах; с ними работает консольная
версия (`main.py`), а скрипт `db/import_json.py` переносит их в базу
SQLite, из которой получает данные веб-интерфейс. Django ORM и формы
еще не используются.

- `data/organizations.json` — организации;
- `data/domains.json` — домены (`organization_id` — владелец);
- `data/certificates.json` — сертификаты (`domain_id`, `organization_id`,
  `valid_from`, `valid_to`, `is_revoked`);
- `data/certhub.sqlite` — база данных SQLite (создается из JSON).

При загрузке JSON консольной версией данные превращаются в объекты
и связи восстанавливаются по идентификаторам; при сохранении объекты
превращаются обратно в данные. Если связанный объект не найден, запись
пропускается с предупреждением.

## База данных SQLite (ПР7)

### Структура таблиц

Таблица `organizations` — организации:

| Поле | Тип | Назначение |
|------|-----|------------|
| `id` | INTEGER | первичный ключ |
| `name` | TEXT, NOT NULL | название |
| `inn` | TEXT, NOT NULL, UNIQUE | ИНН (10 или 12 цифр) |
| `email` | TEXT, NOT NULL | e-mail для уведомлений |

Таблица `domains` — домены:

| Поле | Тип | Назначение |
|------|-----|------------|
| `id` | INTEGER | первичный ключ |
| `name` | TEXT, NOT NULL, UNIQUE | доменное имя |
| `organization_id` | INTEGER, NOT NULL | внешний ключ → `organizations.id` (владелец) |

Таблица `certificates` — сертификаты:

| Поле | Тип | Назначение |
|------|-----|------------|
| `id` | INTEGER | первичный ключ |
| `serial_number` | TEXT, NOT NULL, UNIQUE | серийный номер |
| `cert_type` | TEXT, NOT NULL, CHECK DV/OV/EV | тип сертификата |
| `domain_id` | INTEGER, NOT NULL | внешний ключ → `domains.id` |
| `organization_id` | INTEGER, NOT NULL | внешний ключ → `organizations.id` (заказчик) |
| `valid_from` | TEXT, NOT NULL | начало срока, ГГГГ-ММ-ДД |
| `valid_to` | TEXT, NOT NULL, CHECK > valid_from | окончание срока, ГГГГ-ММ-ДД |
| `is_revoked` | INTEGER, NOT NULL, DEFAULT 0 | признак отзыва: 0 — нет, 1 — отозван |

Связи: одна организация владеет несколькими доменами; у домена может
быть несколько сертификатов; каждый сертификат относится к одному домену
и одной организации. Даты хранятся строками ГГГГ-ММ-ДД, поэтому их можно
сравнивать и сортировать средствами SQL.

### Файлы слоя базы данных

- `sql/schema.sql` — команды `CREATE TABLE` с первичными и внешними
  ключами и ограничениями;
- `sql/queries.sql` — SQL-запросы проекта с комментариями; каждый
  запрос помечен строкой `-- name: <имя>`;
- `db/database.py` — функция `get_connection()`: подключение к
  `data/certhub.sqlite` и включение `PRAGMA foreign_keys = ON`;
  функция `create_schema()` выполняет `sql/schema.sql`;
- `db/import_json.py` — перенос данных из JSON в таблицы
  (`executemany()`, параметры `?`, `commit()` / `rollback()`);
- `db/queries.py` — загрузка запросов из `sql/queries.sql` и их
  выполнение по имени: `fetch_all()` / `fetch_one()` открывают соединение,
  включают `conn.row_factory = sqlite3.Row` и передают значения
  именованными параметрами (`:today`, `:id`, ...).

SQL-запросы не собираются из строк: значения из адреса страницы
(дата, количество дней, идентификатор) всегда передаются параметрами.

### SQL-запросы (`sql/queries.sql`)

| № | Имя | Что возвращает | Конструкции |
|---|-----|----------------|-------------|
| 1 | `summary` | количество организаций, доменов, сертификатов, средний срок | COUNT, SUM, AVG, подзапросы |
| 2 | `domain_list` | домены с владельцем, числом сертификатов и сроком защиты | JOIN, LEFT JOIN, GROUP BY, MAX |
| 3 | `domain_detail` | один домен с владельцем | JOIN, WHERE, GROUP BY |
| 4 | `domain_certificates` | история сертификатов домена со статусом | WHERE, CASE |
| 5 | `unprotected_domains` | домены без действующего сертификата на дату | WHERE, подзапрос NOT IN, JOIN |
| 6 | `certificate_list` | все сертификаты со статусом и остатком дней | JOIN трех таблиц, CASE |
| 7 | `certificate_detail` | полная информация о сертификате | JOIN, WHERE |
| 8 | `expiring_certificates` | сертификаты, истекающие в ближайшие N дней | WHERE, BETWEEN, JOIN |
| 9 | `status_counts` | количество сертификатов в каждом статусе | COUNT, GROUP BY |
| 10 | `type_statistics` | количество и сроки по типам DV/OV/EV | COUNT, AVG, MIN, MAX, GROUP BY |
| 11 | `organization_statistics` | домены и сертификаты каждой организации | LEFT JOIN, COUNT, SUM, GROUP BY |
| 12 | `large_organizations` | организации, у которых не меньше N доменов | JOIN, GROUP BY, HAVING |

Статус сертификата на дату вычисляется в SQL выражением `CASE` по тем же
правилам, что и метод `Certificate.get_status()`; тесты проверяют, что
результаты совпадают.

### Создание базы и проверка запросов

Создать (или пересоздать) базу и перенести данные из JSON:

```
python -m db.import_json
```

Выполнить все запросы файла на текущей базе и вывести результаты:

```
python -m db.queries
```

Проверка в SQLite CLI:

```
sqlite3 data/certhub.sqlite
.parameter set :today "'2026-10-25'"
.parameter set :date "'2026-10-25'"
.parameter set :id 3
.parameter set :days 30
.parameter set :min_domains 2
.read sql/queries.sql
```

## Веб-интерфейс

| URL | View-функция | Страница |
|-----|--------------|----------|
| `/` | `homepage.views.index()` | главная: сводка по статусам, сертификаты для продления |
| `/domains/` | `domains.views.domains()` | список доменов со статусом текущего сертификата |
| `/domains/<int:domain_id>/` | `domains.views.domain_detail()` | домен, владелец, защита на сегодня, история сертификатов |
| `/domains/unprotected/?date=` | `domains.views.unprotected_domains()` | поиск доменов без действующего сертификата на дату |
| `/certificates/` | `certificates.views.certificates()` | таблица сертификатов по дате окончания |
| `/certificates/<int:certificate_id>/` | `certificates.views.certificate_detail()` | сертификат: тип, домен, организация, срок, статус |
| `/certificates/expiring/?days=` | `certificates.views.expiring_certificates()` | сертификаты, истекающие в ближайшие N дней |
| `/certificates/statistics/` | `certificates.views.statistics()` | статистика по статусам, типам и организациям |

Если домен или сертификат с указанным идентификатором не найден,
страница возвращает код 404. Для адресов без маршрута подключен
собственный обработчик `handler404` (`homepage.views.page_not_found()`),
он показывается при `DEBUG = False`.

Путь данных страницы: база SQLite → SQL-запрос из `sql/queries.sql` →
view-функция (`fetch_all()` / `fetch_one()`, строки `sqlite3.Row`) →
контекст → шаблон Django. Представления не формируют HTML в Python и не
содержат текстов SQL: они выбирают запрос по имени, передают параметры
(сегодняшнюю дату, идентификатор из URL, значения из формы) и вызывают
`render()`. В шаблоне поля строки доступны по именам: `{{ domain.name }}`,
`{{ certificate.days_left }}`. Даты из базы выводятся собственным фильтром
`|ru_date` (`homepage/templatetags/certhub_filters.py`).

## Шаблоны Django

### Базовый шаблон и наследование

`templates/base.html` — общий каркас всех страниц: HTML-документ,
Bootstrap, собственный CSS, шапка с логотипом, навигация, подвал
и подключение JavaScript. Дочерние шаблоны наследуют его
(`{% extends "base.html" %}`) и переопределяют блоки
`{% block title %}` и `{% block content %}`.

### Включаемые шаблоны

| Шаблон | Что отображает | Где подключается |
|--------|----------------|------------------|
| `templates/includes/navigation.html` | навигация, активный раздел подсвечивается | `base.html` |
| `domains/includes/domain_card.html` | карточка домена: владелец, зона, защита | список доменов, страница домена |
| `certificates/includes/certificate_status.html` | бейдж статуса сертификата | списки и страницы доменов и сертификатов |

Параметры передаются через `with`:
`{% include "domains/includes/domain_card.html" with is_detail_page=True %}`.

### Контекст, циклы и условия

Представления передают данные словарем контекста, например
`{"domain_rows": [...]}` для списка доменов или `{"certificate": ...,
"row": ...}` для страницы сертификата. Списки выводятся циклом
`{% for %}` с веткой `{% empty %}` для пустой коллекции. Условия `{% if %}`
выбирают цвет статуса (действует / скоро истекает / истек / отозван /
еще не действует), показывают «нет сертификата», «домен не защищен»
и сообщение «не найден» на страницах деталей (в этом случае ответ
имеет код 404).

### Именованные URL и пространства имен

У каждого приложения задан `app_name`; ссылки в шаблонах строятся только
через `{% url %}`:

- `homepage:index`;
- `domains:list`, `domains:detail`;
- `domains:unprotected`;
- `certificates:list`, `certificates:detail`;
- `certificates:expiring`, `certificates:statistics`.

Навигация: Главная | Домены | Сертификаты | Статистика. Поиск незащищенных
доменов открывается со страницы доменов, список сертификатов для
продления — со страницы сертификатов.

### Фильтры шаблонов

Фильтры используются только для отображения данных:

- `|length` — количество организаций, доменов, сертификатов;
- `|default:"Без названия"` — значение по умолчанию;
- `|ru_date` (собственный) — даты ГГГГ-ММ-ДД из базы в виде ДД.ММ.ГГГГ;
- `|floatformat:0` — средний срок действия в статистике;
- `|yesno:"да,нет"` — признак отзыва сертификата;
- `|upper` — серийный номер и доменная зона.

### Статические файлы

Статика находится в `homepage/static/homepage/` и подключается в
`base.html` через `{% load static %}` и `{% static %}`:

- `css/style.css` — собственное оформление: шапка, карточки доменов,
  бейджи статусов, сводка на главной, счетчик оставшихся дней;
- `js/main.js` — текущий год в подвале и быстрый фильтр таблицы
  сертификатов;
- `img/logo.png` — логотип (щит с замком) в шапке.

## Операции веб-интерфейса

### Доступно в браузере

- просмотр доменов и статуса их текущих сертификатов;
- просмотр домена: владелец, защита на сегодня, история сертификатов;
- поиск доменов, не защищенных на выбранную дату;
- просмотр сертификатов, их сроков и статусов;
- список сертификатов, истекающих в ближайшие N дней;
- статистика: статусы, типы сертификатов, организации, крупные клиенты;
- сводка на главной странице.

### Отложено до следующих работ (работает в консольной версии)

Операции, изменяющие данные, появятся в веб-интерфейсе вместе с формами
и POST-запросами: добавление организаций и доменов, выпуск, продление
и отзыв сертификатов.

    ├── conftest.py      — временная база SQLite для тестов

Функции из ПР1 сохранены: `is_valid_term()`, `get_expiry_date()` и
`get_days_left()` перешли в методы класса `Validity`,
`get_certificate_status()` осталась функцией модуля `models/certificates.py`.

Отдельное Django-приложение для организаций не создавалось: организация
отображается на страницах доменов и сертификатов, а пользователи системы
появятся в теме аутентификации (встроенная модель `User` Django).

## Требования

- Python 3.11+;
- Django 5.2;
- pytest;
- flake8.

Установка зависимостей:

```
pip install -r requirements.txt
```

## Запуск

Веб-версия (база `data/certhub.sqlite` уже лежит в репозитории;
при необходимости ее можно пересоздать из JSON командой
`python -m db.import_json`):

```
python manage.py migrate
python manage.py runserver
```

После запуска открыть http://127.0.0.1:8000/

Консольная версия (сохранена):

```
python main.py
```

## Запуск тестов

```
pytest -v
```

Тесты проверяют создание объектов и их атрибуты, методы классов,
взаимодействие объектов, правила выпуска сертификатов, загрузку/сохранение JSON,
страницы Django-приложения и коды ответов 200/404, а также слой SQLite:
создание таблиц и внешних ключей, импорт из JSON, выполнение всех
SQL-запросов, совпадение статусов в SQL и в классе `Certificate`,
передачу значений параметрами. Тесты работают с временной копией базы
и не изменяют `data/certhub.sqlite`.

## Проверка качества кода

```
flake8 . --extend-exclude=venv
```

Перед защитой также полезно выполнить `python manage.py check` и
`python manage.py findstatic homepage/img/logo.png`.
